## End-of-session decision — 2026-04-30

**Question:** Does the walk-through structure produce useful extraction, or does the experimental framing's structure (not just content) need adjusting?

**Inputs to the decision:**
- 3 walk-through docs authored ([STORY-001](../STORY-001-persona-model-fit.md), [STORY-006](../STORY-006-v-invariant-adoption.md), [STORY-012](../STORY-012-merchant-explainability-demand.md)).
- 1 walk-through run completed ([STORY-001 with self in PM-role](STORY-001-2026-04-30-nino-pm-role.md)).
- 0 walk-throughs run with cold audience.

### Decision

**The walk-through structure is sound and worth keeping. The doc-shape is not the problem — the operational prereqs are.** Three concrete fixes to the structure (not the framing) before the next run:

1. **Pre-warm the artifact before each session.** The 10s cold-start latency is real; running the walk-through cold means 60–90s of dead air on transitions. The walk-through doc should require the host to hit each `?intent=` URL twice before the audience arrives so all four landings are cache hits. Without this, the demo loses rhythm and the audience's attention drifts during loading. Add to STORY-001 prereqs.

2. **Decide the Observe story before the next CS run.** `/observe` requires a key in production. STORY-001 and STORY-012 both reference it as a live diagnostic. Three options, pick one before a real audience touches the doc:
   - (a) Document the key step explicitly in the walk-through prereqs and share the key with the host.
   - (b) Build a non-gated, read-only "Inspector preview" route that shows a static or session-bound trace.
   - (c) Replace the live Observe portion with annotated screenshots in the walk-through doc and run live only when host has dev access.
   Option (b) is the most aligned with the Phase 4 Inspector goal but is real engineering work. Option (a) is operationally fine and ships today. Decide which.

3. **Calibrate the PRD/BRD acceptance criteria against what the artifact actually does.** The PM-role run surfaced that PRD-ENG-009 oversells researcher-persona structural distinctiveness — the persona modulates copy more than blocks. Walk-throughs with audiences who read the BRD first will hit this disconnect. Either (i) sharpen the artifact to match the PRD claim, or (ii) edit the PRD/BRD to match the artifact. The walk-through doc should not promise what the artifact doesn't deliver.

### What the framing got right (don't change these)

- **One walk-through per story.** The 1-page constraint forced specificity. The bring-back template fits because it's the closing third of the page, not an appendix.
- **The bring-back template is the artifact, not the walk-through itself.** The structural test of a successful run is "did the audience fill in the template with verbatim, falsifiable content" — and the PM-role run did, even where the answer was "modify, not adopt." The template's "inconclusive" option also matters: it gives the audience a graceful exit instead of forcing a fake recommendation, and it surfaces what additional data would close the question.
- **"What to bring back" is audience-filled, not host-prescribed.** Walk-throughs that pre-fill recommendations would produce echo-chamber bring-backs. The framing's asymmetry (host names what to look at; audience names the conclusion) is correct.
- **Failure modes are explicit and named in the walk-through.** The "if the audience says 'neat' with empty bring-back, escalate per RISK-07" line in STORY-001 is the structural defense against vanity-demo capture. Keep this.

### What we don't know yet

The structural test is inconclusive on one axis: **whether a cold audience (a real PM, engineer, or CS team member without prior context) extracts useful content.** The PM-role run was the walk-through's author. The bring-back was honest but reflects me-as-PM-on-this-artifact, not a randomly-sampled PM. Two walk-through runs with cold audiences would flip the structural test from "doc reads coherently" to "doc produces extraction" — that's the real RISK-07 mitigation.

This is the gating signal for the experiment: until we get one cold audience run per audience, the experiment hasn't been tested at the level it claims to test the hypotheses.

### Decision summary

**Keep the experimental framing.** The structure does what RISK-07 asked it to do: it forces audiences to produce artifacts (not reactions) and it makes "neat with empty bring-back" a recognizable failure rather than an ambiguous outcome. The fixes are operational, not framework-level.

**Call the structure tested only after one cold-audience run per audience.** Today we have 0/3. The bare minimum threshold is 1/3; the comfortable threshold is 1/audience × 3 audiences = 3 runs. Until then, RISK-07 remains live.

**The artifact's first observable gap is calibration, not capability.** PRD/BRD claims overshoot the artifact in places (researcher structural distinctiveness; full Decisions Inspector). Calibration drift is normal at this stage but invisible until walk-throughs surface it — meaning the walk-through structure is *already* working at the level of artifact debugging, even before producing audience extraction. This is a positive signal.
