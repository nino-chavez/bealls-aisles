**Version**: 0.1.0
**Last Updated**: 2026-04-06
**Audience**: Demo Presenters, Sales Engineers

> **Historical note (2026-05-02):** This script describes the upstream `aisles-storefront` demo flow against the synthetic reference brands (Haven, Volt, Ember). The active Bealls fork's demo reel v3 (`scripts/demo-reel/out/demo-reel.mp4`) walks the same beats against bealls / Bealls Florida / Home Centric. The structural choreography below — first impression, Observe walkthrough, persona shift, brand swap, refinement, cost close — still applies; only the brand names and URLs differ. Treat this script as the canonical demo *structure*; substitute the current Vercel project URLs (`aisles-demo-{1,2,3}-signal-x-studio-labs.vercel.app`) and Bealls family banner names when running it live.

## Setup

Open two browser windows side by side — or use a split-screen tool. If presenting on a projector, put both windows on the extended display before starting.

**Left window** (the storefront — shopper's perspective):
```
https://aisles-signal-x-studio-labs.vercel.app
```

**Right window** (Observe dashboard — your perspective):
```
https://aisles-signal-x-studio-labs.vercel.app/observe?key=aisles-observe
```

Before presenting, open the storefront in a private/incognito window so you start with a fresh session (no stored persona, no cross-session signals). The Observe window can be in a regular window.

After loading the storefront homepage, switch to the Observe window and select the new session from the dropdown. Enable "Watch latest" if you want it to auto-track.

## Step 1: Haven Storefront — First Impression (2 min)

**What to do**: On the storefront, navigate to **Living Room** from the nav.

**What to say**:

"This is Haven — a mid-market furniture brand. What you're looking at is a category page generated by an AI in real time. There's no manually built template here. The AI decided what sections to show, which product to feature, what copy to write, and how to arrange the grid."

Pause on the layout. Point out:
- The editorial header copy (specific, warm — not generic)
- The hero product placement
- The image aspect ratio and grid density

"This is the default view — a fresh visitor with no signals. The engine defaults to the Gatherer persona: someone browsing for inspiration, not buying yet. So it leads with editorial content and gives products room to breathe."

**On the Observe window**: show the Persona Vector panel. Point out:
- `gatherer` is the primary with the highest probability
- `signalCount` is low (only request-time signals fired: pageview, device type)
- The prior is clearly visible — gatherer's base weight of 0.30 is dominant

## Step 2: Observe Dashboard — Making the Invisible Visible (2 min)

**Stay on the Observe window for this step.**

"This is what's happening behind that storefront. Every signal the system receives shows up here in the Signal Timeline."

Walk through the signal timeline:
- `request.pageview` — the page loaded
- `request.device` — the engine knows it's a desktop browser
- If there's a referrer, point it out

"These are request-time signals — available before the page even renders. The engine uses them to make an initial guess."

Point to the Layout Decision panel:
- "This generation hit the cache — someone already visited this page, so it returned in under 100 milliseconds. Zero AI cost."
- OR "This was a cache miss — the AI generated this layout in [X] seconds using Claude Haiku. Cost: [X] cents."

"Every generation is logged here — model, time, tokens, cost. A full demo session like this one typically costs less than a penny."

## Step 3: Persona Shift — The Moment That Lands (3 min)

**What to do**: On the storefront, use the search bar. Search for:
```
dorm room desk
```

Wait for the results page or category redirect. Then navigate to the **Office** category.

**What to say**:

"Watch what happens when I search for 'dorm room desk.'"

Switch to Observe. Point to the Signal Timeline:
- A `nav.search` event just appeared with `query: "dorm room desk"`

Point to the Persona Vector:
- "The engine just re-ran inference with that search query. Budget keywords — 'dorm,' 'desk' — fired the hunter rules. Watch the bars."

If a shift is detected, the alert should be showing:
```
SHIFT DETECTED
gatherer → hunter
trigger: search query "dorm room desk" conflicts with stored gatherer model
```

"The persona just flipped. Gatherer to Hunter. That search tells the engine this isn't an inspirational browser — this is someone with a goal and a budget constraint."

Switch back to the storefront and navigate to Office:
- "The layout responded. No editorial header. Category header with sort and filter controls. Dense 4-column grid. Quick-add buttons. The exact experience a Hunter expects."

Point back to Observe:
- "And here's the generation: cache miss, Haiku model, [X] milliseconds. New layout, same catalog, completely different presentation."

## Step 6: Refinement Chat (2 min)

**What to do**: Return to Haven. Navigate to **Living Room**. Find the refinement chat interface (usually a chat icon or panel at the bottom of the category page). Type:

```
I need something for a small apartment under $800
```

Wait for the layout to update. Then send a follow-up:

```
show me something with natural materials
```

**What to say**:

"The refinement chat lets the shopper steer the layout through conversation. Each message becomes a constraint that stacks with previous ones. 'Small apartment under $800' filters by price and size. 'Natural materials' further narrows by material type."

Switch to Observe:
- "The refinement generated a new layout — cache miss, because constraints are session-specific and can't be cached."
- Point to `constraintCount: 2` in the meta
- "Two constraints accumulated. The AI has context from both messages, not just the last one."

Point to the Layout Decision panel:
- "Type is 'refine' — different from 'layout.' Same model selection (Haiku first), same logging, but no cache."

## Key Talking Points

Use these when audience questions come up, or weave them into the walkthrough:

**"How does it know what persona to use?"**
It doesn't start from zero. It uses observable signals available on every HTTP request: search query, referrer, UTM tags, device type, time of day, and any cross-session history. No login required, no tracking pixels, no third-party data. Just the signals the shopper reveals through their own behavior.

**"What if it guesses wrong?"**
The refinement chat is the escape hatch. If the layout doesn't match the shopper's intent, they can tell it what they actually want. The engine accumulates those constraints and regenerates. The whole system is designed to correct rather than lock in.

**"Is the copy human-written?"**
The structure and product selection are AI-generated. But the AI is working from a detailed brief — persona definitions, voice guidelines, anti-patterns, and product enrichment data. Haven's editorial copy doesn't happen because the AI is generally good at writing; it happens because the brand config tells it specifically what warm-and-editorial means for a furniture store, and the enrichment data tells it which products have high storytelling potential.

**"How do you add a new brand?"**
Write the brand config (channel ID, categories, theme colors, persona definitions, voice guidance). Run the enrichment pipeline against the new channel's products. Deploy a new Vercel project with `BRAND_ID` set. That's it. The AI adapts to the new domain and aesthetic from the config — you don't rewrite the application.

**"What happens when AI generation is slow?"**
The streaming endpoint (`/api/layout/stream`) sends partial layout objects as they generate. The editorial header appears in about one second, before the product grid is ready. The shopper sees progressive content rather than a blank skeleton. For subsequent visitors, the Redis cache makes it instant.

**"Is this a BigCommerce-only solution?"**
The catalog layer is BigCommerce today, but it's abstracted behind `loadCategoryProducts`. The inference engine, layout schema, AI generation, and caching layers have no BigCommerce dependencies. Replacing the catalog source is a data-layer swap, not a system rewrite.
